# Required CI retention coverage

`npm run test:ci:db` is the connected entry point in **both** required MySQL and MariaDB jobs. It runs the complete ordinary Vitest suite with `runPrismaTests=true`; no files or assertions are excluded. The raw result is `artifacts/vitest-db-report.json`.

It then bootstraps the existing safe-filesystem fixture runner only on an ephemeral GitHub-hosted Linux runner, with explicit `--ci-multi-uid`. `sudo -n env -i` is confined to this CI bootstrap; it is not a local-host remediation. The test process enters private user/mount/network/PID namespaces and a disposable chroot before testing. Only UID/GID 0 and 1 are mapped. No host bind mounts, Docker socket, production environment/data, network payloads, sysctl edits or ancestor chmod are used. Copies are allowlisted, reject nested symlinks/special files and have a 512 MiB / 25,000-file ceiling; execution has CPU/file/heap/wall-time limits and namespace child termination. Cleanup removes only the newly allocated fixture tree.

Inside that same isolation, a mandatory probe performs actual `chown(..., 1, 1)`, verifies `stat`, and records `/proc/self/{uid,gid}_map`. Capability failure fails CI before Vitest; it never creates passing evidence. The real foreign-owner rejection test also checks actual ownership and no longer calls `context.skip()`.

The offline run executes the complete operational-filesystem and historical-preparation files, including all 15 filesystem and all 7 real report/config → adapter → CLI composition cases. Its raw JSON, capability probe and exit status are exported as `artifacts/vitest-safe-report.json`, even when testing fails if a report exists. `assert-vitest-report.mjs` independently requires this entire report to pass without skips.

`merge-retention-vitest-reports.mjs` validates declared totals against assertions and reconciles the 22 safe-only ordinary skips by **relative file + full test name**, not totals alone. It requires successful execution, exactly two mapped owners, and the actual foreign-owner test passing. Unknown skips, missing/mismatched/duplicate safe identities, failed/todo assertions, unsuccessful execution, failed probe or nonzero safe exit fail closed. Ordinary parameterized tests with identical rendered names remain separate passed occurrences; they cannot supply replacement evidence. Every ordinary assertion remains in `artifacts/vitest-report.json`; replaced assertions carry actual isolated assertion results and a provenance list. The unchanged no-skips gate checks the final report. All subprocess statuses also affect the job exit, so aggregation cannot mask a failed process. All three reports are uploaded by each DB job, including raw diagnostics on failure.

## Local verification is not hosted CI certification

The unprivileged local mode maps only the current UID to 0. On a host without subordinate UID tooling, UID 1 is genuinely unavailable (`chown` returns `EINVAL`); the foreign-owner case fails rather than skips. Do not use local sudo, change host namespace policy, loosen file guards, fabricate ownership, or edit reports to make this pass. Local tests can establish the other 21 formerly skipped cases and report/gate regressions, but a successful multi-UID run and both DB jobs must be read back from hosted CI after review/push. This change does not alter service guards, runtime apply, production gates, deployment, restore or trust roots.

## MUST-FIX subprocess regressions and dependency port

The fixture entry point now calls `runSafeNamespace` with a mandatory `SIGKILL` timeout signal and retains `unshare --fork --kill-child`. `unshare --fork` ignores `SIGTERM` while waiting, so the former synchronous timeout could return only after the child completed. The exported shared helper is exercised with real unprivileged `unshare`, not a detached comparison. The regression proves that a child started, return is bounded, and the child's delayed completion marker remains absent after its scheduled completion. The production fixture retains the private PID namespace, so killing its namespace init also tears down descendants. No local sudo or host configuration is used by the regression.

The DB entry point uses the same exported `run` and `runDatabaseCoverage` functions tested by the process regressions. Its unchanged 600-second timeout now uses `killSignal: 'SIGKILL'`, making termination effective for a direct child that ignores `SIGTERM`. This is **direct-child termination, not process-tree cleanup**: inherited stdio does not kill grandchildren, and killing the direct `sudo` bootstrap is not proof that its descendants died. The safe namespace runner separately retains its own 300-second deadline, `SIGKILL`, `--kill-child` and private PID-namespace teardown. For other descendants outside that isolation, the hosted DB jobs' existing 25-minute job timeout / ephemeral-runner teardown remains the fallback; no blanket descendant-cleanup guarantee is claimed. No process-group signalling or host-wide cleanup was added. Every `spawnSync` error or signal fails regardless of a coincident zero status; all five phases remain mandatory and diagnostic. Exported safe-report execution metadata also records errors/signals as failure. Importing the module does not execute the hosted bootstrap; running its actual entry point locally still refuses before subprocesses/artifact writes. The Node test file is `.node.mjs` because it is a separate mandatory Node test-runner suite, invoked by the quality job, not a Vitest file or a Vitest skip.
