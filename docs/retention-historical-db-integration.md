## Isolated target admission

Both entry and integration enforce `GITHUB_ACTIONS=true`, `RUNNER_ENVIRONMENT=github-hosted`, explicit `RETENTION_HISTORICAL_DB_CI=1`, the declared `mysql` or `mariadb` engine and the exact pre-existing loopback `mailgun_ci` service URL with the fixed CI-only user/credential/port. No alternate host, database, port, username, password, query parameters or URL fragment is accepted. The child receives a small explicit environment; host secrets, NODE_OPTIONS and arbitrary dotenv/preload configuration are not forwarded. Public CI flags are accidental-use guards, **not authentication of hostile PR code**.

Before mutation, native SQL checks DATABASE(), CURRENT_USER(), VERSION(), the expected MySQL 8.0 / MariaDB 11.4 service family and all five target tables' InnoDB engines. The separately constructed Prisma+MariaDB-adapter client checks its own database/user. A SQL catalog fingerprint is calculated from actual ordered information_schema scalar rows (table, column, ordinal, type, nullable, key, extra). The exact Prisma source bytes are hashed separately; these domains must differ. This bounded test procedure is not an approved production catalog/provenance collector or full schema certification.

Only the existing hosted GitHub service jobs execute SQL. No additional image, local database or dependency/lock change is needed.

### Engine-compatible native timeouts

The guarded target feeds `historicalNativeConnectionOptions` in the dedicated wrapper module; the integration's actual `mariadb.createConnection` consumes that builder. Unknown engines throw instead of falling back. Both engines retain explicit `connectTimeout: 5000`, `socketTimeout: 10000`, UTC and string dates. Only MariaDB receives global `queryTimeout: 10000`: the installed driver initializes it as `SET max_statement_time=10` on supported MariaDB versions, but rejects it on MySQL with `ER_TIMEOUT_NOT_SUPPORTED` (45038) during connection initialization.

MySQL therefore has no global driver queryTimeout/server-wide statement limit. Its native connection retains the client socket inactivity timeout and `innodb_lock_wait_timeout = 1` session lock bound; these are not a universal wall-clock SQL statement deadline or proof of server-side cancellation. MySQL `MAX_EXECUTION_TIME` applies only to eligible SELECT statements and is not substituted for a general SQL timeout. Prisma pool limits remain `connectTimeout: 5000`, `acquireTimeout: 5000`, with the existing Serializable transaction `maxWait: 5000`, `timeout: 30000` unchanged. Wrapper and hosted-job deadlines remain fail-closed with the direct-child/unknown-outcome limitations above.

Offline regression invokes the installed ESM driver's real `Connection.prototype.executeSessionTimeout` on a synthetic receiver, passing the exact builder output. The MariaDB query method is only an observer resolving the driver's Promise executor; no connection constructor, socket or SQL execution occurs. This proves option compatibility and captures the generated MariaDB initialization SQL, not real session initialization, statement cancellation or database outcomes.

### Strict catalog ordinal serialization

The MariaDB hosted failure was `TypeError: Do not know how to serialize a BigInt` at `catalogFingerprint`, before the eight-case loop. Installed driver inspection confirms ordinary row records in SELECT projection order, numeric INT decoding and default BigInt BIGINT decoding; this harness does not enable numeric-string options. No driver/dependency/global JSON setting is changed.

`catalogFingerprint` now passes its actual query rows to the pure `serializeHistoricalCatalogRows` in `scripts/retention-historical-catalog.mjs`, then hashes those serialized bytes. It requires a nonempty row array, exact seven own enumerable data fields on non-array plain/null-prototype records, and primitive strings for all six non-ordinal fields (including valid empty key/extra strings). Only `ORDINAL_POSITION` accepts number or bigint: a positive safe integer, with the bigint range checked **before** Number conversion. Zero, negatives, fractions, unsafe values, numeric strings, booleans, arrays, null, wrappers, extra/missing fields and accessors are rejected rather than coerced. No replacer, blanket String conversion, `BigInt.prototype.toJSON`, manufactured catalog or production import is added.

Canonical object field order matches the unchanged SELECT projection; SQL row order is retained without sorting. Valid numeric MySQL rows in that projection order keep the old JSON bytes exactly. Matching MariaDB BigInt ordinals yield the same JSON/hash, without mutating native rows; this equality applies only when all actual catalog fields match, not as a claim that different engines have identical catalogs. Every field and row ordering remains fingerprint-sensitive. The module is used only by the hosted integration and its existing required Node regression suite; the safe snapshot allowlist is unchanged.

## Connected path and finite fixtures

Each scenario owns eight fixed synthetic rows: target B/M/E/N plus an unrelated parent/message/notification and an unrelated orphan. Absence of the exact finite IDs is checked before taking ownership; INSERT and cleanup are native SQL restricted to those IDs. A collision refuses without deleting pre-existing rows. The archive includes an excluded parent and a notification afterimage; only the approved target B/M/E/N selection may be deleted. Sentinel scalar rows and unrelated orphan are compared before/after every attempt, and cleanup is independently read back.

Native SQL independently reads every target scalar, frames the original encoding and calculates the digest report before signing with a fresh test-only Ed25519 principal. The helper refuses if these native digests differ from archive selection; it never generates database readback from archive expectations. Synthetic image/config, principal/procedure and non-DB queue/Ghost/proxy/pressure observations are test contracts, not live infrastructure claims. SQL schema/correlation gates observe the actual native connection.

The real envelope stream feeds `createInternalHistoricalRetentionExecutor`, authenticated acquisition and private admission, then **actual Prisma `$transaction(..., Serializable)`**, the shared child-first deletion core, and native second-session postcommit reads. A Proxy observes/injects around real Prisma delegate calls; it does not replace SQL reads/deletes or emulate transaction outcomes. Actual SQL session IDs must differ.

Serializable behavior is probed after the ordinary transactional parent SELECT: an independent native writer attempts a no-op UPDATE in its own transaction, must observe native lock-wait timeout 1205, and rolls back. This checks read-lock behavior, not just the requested option. `@@transaction_isolation` / `@@tx_isolation` are deliberately not presented as proof: the installed adapter uses per-transaction `SET TRANSACTION`, whereas those variables describe the session default. The artifact's `isolation` marker records the successful behavioral probe, not a direct variable read.

## Required acceptance matrix (MySQL old-head proof complete; MariaDB and combined-head proof pending CI)

| Scenario | Required executor state | Required native observation |
|---|---|---|
| commit | `committed_readback_ok` | Four target rows deleted, second-session counts zero, sentinels unchanged |
| rollback-after-delete | `rollback_confirmed` | Real notification DELETE + in-transaction zero count before injected exception; native complete rows equal before/after; independent FOR UPDATE succeeds after rejection; confirmation bound to this attemptId |
| precommit-divergence | `rollback_confirmed` | Native same-count contents UPDATE after acquisition; exact-content rejection, zero executor DELETE, changed baseline rows preserved; released locks and attempt-bound rollback confirmation |
| postcommit-failure | `committed_readback_failed` | Native counts first observe actual committed deletion, then read dependency throws; no rollback confirmation |
| postcommit-mismatch | `committed_readback_failed` | Native counts first observe actual committed deletion, then native SQL re-inserts only the synthetic parent; subsequent native count actually equals one; no fabricated count or rollback claim |
| unsigned | `refused_before_transaction` | No transaction attempt, no DELETE, complete native before/after equality |
| gate-refusal | `refused_before_transaction` | Authenticated synthetic nonzero queue census refuses; no transaction attempt/DELETE, complete native before/after equality |
| commit-unknown | `commit_unknown` | Real transaction commits, synthetic adapter loses the response; no rollback attestation/postcommit call; independent final native counts still observe deletion |

Generic rejection cannot certify rollback. The bounded adapter only attests after the known injected callback failure or exact precommit scalar mismatch, unchanged native scalar rows and independently reacquired row locks. The native confirmRollback read is bound to the exact adapter attemptId. Unknown outcomes are not relabeled, and postcommit failures cannot invoke rollback confirmation.
